## Agent Brief

**Category:** bug
**Summary:** Link/badge "Relatório de amanhã" no scanner e a data default do daily report são congelados no setup; aba aberta antes das 23h nunca os atualiza.

**Current behavior:**
`hasTomorrowReport`, a data de amanhã e a data default do relatório são calculados uma única vez na montagem da página (constant properties). O tick de 1s existente só atualiza `updatedAgo`/`canOpenDrawer`. Consequência: uma aba aberta antes das 23h nunca ganha o link/badge do relatório de amanhã até recarregar; a data default do daily report também fica congelada no dia da montagem.

**Desired behavior:**
Esses valores derivam do tempo atual de forma reativa: quando o relógio cruza as 23h (fuso de SP), a link/badge aparece na aba aberta sem reload; quando o dia vira, a data default do daily report reflete o novo dia. Aba montada depois do horário continua comportando-se como hoje.

**Key interfaces:**
- Disponibilidade do relatório de amanhã no scanner (`hasTomorrowReport`, data de amanhã): devem ser computações reativas ao tempo (ref/computed lido no tick existente), não constantes de setup
- Data default do daily report: deve ser recalculada quando o dia corrente muda, não fixada na montagem
- Tick periódico de 1s já existente: pode servir de gatilho de atualização

**Acceptance criteria:**
- [ ] Aba aberta às 22:59 ganha o link/badge de relatório de amanhã ao cruzar 23h, sem reload
- [ ] Aba aberta antes da meia-noite exibe a data default correta após a virada do dia, sem reload
- [ ] Comportamento de aba montada já depois das 23h inalterado
- [ ] O tick de 1s não passa a fazer work pesado desnecessário (cálculo barato de comparação de horas)
- [ ] Teste cobre a transição 22h→23h e a virada de dia
- [ ] `lint`, `test:unit` e `build` passam

**Out of scope:**
- Regra de disponibilidade do relatório no backend
- Layout do badge/link
- Outras datas/campos das páginas
