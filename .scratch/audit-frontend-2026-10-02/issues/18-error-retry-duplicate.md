## Agent Brief

**Category:** bug
**Summary:** O botão "Tentar de novo" da página de erro deve tentar de novo (reprocessar a rota), em vez de redirecionar para a home — e eliminar os dois handlers idênticos.

**Current behavior:** A página de erro global tem dois handlers com corpo idêntico: ambos fazem `clearError({ redirect: '/' })`. A UI promete retry, mas a ação sempre navega para a home. Código duplicado: um dos dois handlers é desnecessário ou está ligado ao botão errado.

**Desired behavior:** "Tentar de novo" limpa o erro e reprocessa a página/rota que falhou, sem ir para a home. A ação de home (se existir) segue redirecionando para `/`. Cada botão tem uma ação distinta — ou resta um único handler, se a UI tiver um só botão. O comportamento é verificável: falha → clicar retry → a rota é tentada de novo (e se falhar de novo, a página de erro reaparece, sem loop).

**Key interfaces:**
- Página de erro global: a ação de retry deve limpar o erro e recarregar a rota atual (sem `redirect` para a home)
- A ação de home mantém `redirect: '/'`
- Não podem restar dois handlers com corpo idêntico

**Acceptance criteria:**
- [ ] Forçando um erro e clicando em "Tentar de novo", a rota que falhou é reprocessada (não navega para `/`)
- [ ] A ação de home/voltar continua redirecionando para `/`
- [ ] Não restam dois handlers com corpo idêntico na página de erro
- [ ] Se o reprocesso falhar de novo, a página de erro reaparece (sem loop infinito nem branqueamento)

**Out of scope:**
- Estilos/layout da página de erro
- O tratamento de erros globais / captura de exceções
- Mapeamento de códigos de status HTTP
**Wave 3 (2026-10-03):** Implementado, commit `822bf94`. "Tentar novamente" reprocessa a rota (`clearError()` sem redirect); "Ir para o início" mantém o redirect. Os handlers deixaram de ter corpo idêntico. O critério anti-loop foi ancorado no contrato observável (retry sem redirect, home com redirect) por ser comportamento interno do Nuxt. Suíte completa verificada pelo orquestrador: 546/546 verde.
