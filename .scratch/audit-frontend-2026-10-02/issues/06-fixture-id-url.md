## Agent Brief

**Category:** bug
**Summary:** Fixture ID interpolado em URL do Flashscore sem validação de formato

**Current behavior:**
A função utilitária que monta a URL de um jogo no Flashscore interpola o `fixtureId` recebido direto no path, sem validar o formato. O host e o scheme são fixos antes da interpolação, então não há open-redirect nem escape de domínio (sempre termina em flashscore.com.br), mas um valor não-numérico com `/`, `..` ou query manipula o path no site de terceiros. É chamada por vários cards com dados vindos de API. O Vue já evita attribute injection via bind.

**Desired behavior:**
A função deve validar que o `fixtureId` tem formato aceitável (ID numérico/identificador esperado) antes de montar a URL. Para IDs válidos, a URL gerada é idêntica à atual. Para IDs inválidos, a função deve sinalizar claramente (retorno que permite ao chamador não renderizar o link) em vez de gerar URL manipulada — sem lançar exceção não tratada que derrube o card.

**Key interfaces:**
- A função de montação de URL do Flashscore (`.../jogo/${fixtureId}/`): deve checar o formato do `fixtureId` (ex.: só dígitos/identificador seguro) e retornar um sinal de inválidez (ex.: `null`/`undefined` ou flag) quando não passar, em vez de interpolar cru
- Os cards que consomem a função (dailyBet, fixture, fixtureDetails, reportGame): devem tratar o retorno inválido suprimindo o link ao Flashscore, mantendo o resto do card renderizado

**Acceptance criteria:**
- [ ] Um `fixtureId` numérico normal gera exatamente a URL atual (`https://www.flashscore.com.br/jogo/<id>/`)
- [ ] Um `fixtureId` com path traversal/manipulação (`../`, `/`, `?`, `#`, caracteres de query) não é interpolado em URL clicável
- [ ] No caso inválido, o card não quebra: link suprimido (ou não clicável), resto do card renderiza
- [ ] Todos os pontos de uso (cards de dailyBet, fixture, fixtureDetails, reportGame) tratam o retorno inválido
- [ ] Testes unitários cobrem: ID válido → URL correta; ID inválido → retorno de falha

**Out of scope:**
- Trocar o host/scheme fixo do Flashscore ou suportar outros idiomas/domínios
- Validar outros campos de URL vindos de API (fica para a issue 01 com a validação de esquema)
- Alterar a lógica de abertura em nova aba (`target`/`rel`) dos cards
