## Agent Brief

**Category:** enhancement
**Summary:** Remover o campo `allowBuilds` inerte da config do workspace e documentar que o pnpm 9 roda todos os scripts de instalação por decisão do projeto.

**Current behavior:**
A config do workspace do pnpm declara uma whitelist `allowBuilds` (quais scripts de build de dependências podem rodar), mas o gerenciador fixado no projeto é pnpm 9, que não suporta esse campo e roda todos os scripts de instalação de dependências por padrão. O campo é ignorado: a proteção anunciada não está em vigor e transmite falsa sensação de segurança.

**Desired behavior:**
A config do workspace não contém campos que o gerenciador fixado ignora. Fica documentado, em documentação versionada no repo, que com o pnpm fixado todos os scripts de instalação de dependências rodam no install — e que isso é uma decisão consciente do projeto.

**Key interfaces:**
- Config do workspace do pnpm: campo `allowBuilds` removido (nada de campo inerte)
- Documentação do projeto: nota explícita sobre o comportamento do pnpm fixado (todos os postinstalls rodam) e a decisão de mantê-lo assim
- Pinagem do gerenciador: inalterada — a versão fixada do pnpm continua a mesma

**Acceptance criteria:**
- [ ] A config do workspace não contém mais `allowBuilds`
- [ ] A decisão está documentada em arquivo versionado do repositório (o que roda no install e por quê)
- [ ] A versão fixada do pnpm não mudou
- [ ] Instalação e lockfile se comportam exatamente como antes (nenhuma mudança de dependências)

**Out of scope:**
- Subir/bumpar a versão do pnpm para 10+
- Adicionar mecanismo alternativo de aprovação de scripts
- Auditar individualmente quais scripts rodam (só documentar o comportamento)
