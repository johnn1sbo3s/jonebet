## Agent Brief

**Category:** bug
**Summary:** Ordenação da lista de fixtures faz `sort` in-place na prop, mutando silenciosamente o array do componente pai.

**Current behavior:**
Ao derivar a lista interna, o componente ordena por hora usando o próprio array recebido via prop (`value.sort(...)`) e guarda o resultado. Como `sort` ordena in-place e devolve a mesma referência, o array do pai é reordenado sem que ele peça. O estado do pai é modificado pelo filho (anti-patrão Vue), a ordem original da API é perdida e o comportamento quebra se o pai reaproveitar ou comparar o array.

**Desired behavior:**
A ordenação opera sempre sobre uma cópia; a prop nunca é mutada. A lista exibida continua ordenada por hora crescente. O componente pai mantém o array exatamente na ordem em que o passou, mesmo após a lista filha renderizar.

**Key interfaces:**
- Prop `fixtures` (array de fixtures): deve ser tratada como read-only pelo componente
- Lista interna derivada (`internalFixtures` ou equivalente): construída a partir de uma cópia (`[...value]`/`slice()`) antes do `sort`

**Acceptance criteria:**
- [ ] Depois de montar a lista com um array desordenado, o array do pai permanece com a ordem original (nenhuma mutação in-place)
- [ ] A ordem exibida na tela segue sendo por hora crescente (comportamento visual preservado)
- [ ] Teste de regressão cobre: pai passa array desordenado → após render, ordem/identidade do array do pai inalterada
- [ ] `lint`, `test:unit` e `build` passam

**Out of scope:**
- Mudar o critério de ordenação (continua por `Time`)
- Normalização de fusos/formatos de horário
- Outros componentes que recebem a mesma prop
