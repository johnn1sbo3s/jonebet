## Agent Brief

**Category:** bug
**Summary:** Query param `date` da busca de modelos de trading montada por concatenação sem URL-encoding

**Current behavior:**
O composable que busca modelos de trading diárias monta a URL da API concatenando o valor da data direto na query string (`?date=${...}`), sem `encodeURIComponent`. Outros composables do mesmo projeto (relatório diário, análise pré-jogo) já usam `encodeURIComponent` — há inconsistência. Hoje o valor vem de um DatePicker interno (não de `route.query`), então não é explorável por input atacante, mas se a data algum dia vier de URL seria injeção de query/request malformado.

**Desired behavior:**
O valor da data deve ser URL-encoded ao ser interpolado na query string, seguindo o mesmo padrão já adotado pelos demais composables. A requisição para a API de modelos de trading deve continuar funcionando identicamente para datas no formato atual, e a montagem da URL deve ser robusta a qualquer valor de data (incluindo valores malformados ou vindos de fonte externa no futuro).

**Key interfaces:**
- O composable de trading models e sua construção da URL de `/trading-models/daily`: o parâmetro `date` deve passar por `encodeURIComponent` antes da concatenação, igual aos composables de daily report e pre-game analysis
- O ref de data (`dateRef`) e seu formato de origem: não precisa mudar

**Acceptance criteria:**
- [ ] A query param `date` é passada por `encodeURIComponent` na montagem da URL
- [ ] Uma data no formato normal (ex.: `2026-10-03`) continua gerando a mesma requisição funcionando à API
- [ ] Um valor de data contendo caracteres especiais (`&`, `=`, espaços, `#`) não quebra a query string nem injeta parâmetros extras
- [ ] `npm run lint`/`test:unit` passam sem regressão

**Out of scope:**
- Alterar o formato da data ou a API do endpoint
- Refatorar os outros composables que já fazem encoding correto
- Ler a data de `route.query` (hoje ela vem do DatePicker interno)
