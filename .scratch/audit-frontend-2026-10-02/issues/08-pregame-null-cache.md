## Agent Brief

**Category:** bug
**Summary:** Resultado `null` da análise pré-jogo não pode ser cacheado como `done` permanente — o retry deve conseguir buscar o relatório quando ele passar a existir.

**Current behavior:** A primeira abertura do modal tenta buscar o relatório da noite em duas tentativas de origem; se nenhuma retornar dado (relatório ainda não gerado), o resultado `null` é gravado no cache com status `done`. O botão de retry chama a mesma rotina de carga, que encontra o cache e devolve o `null` imediatamente. A análise nunca aparece até o usuário recarregar a página, mesmo depois que o pipeline gera o relatório.

**Desired behavior:** Quando a busca não encontra relatório (nada a exibir), o estado deve indicar "indisponível, pode tentar de novo" e permanecer passível de nova tentativa. O retry deve efetivamente refazer a requisição; quando o relatório já existir no servidor, a análise aparece sem reload. Cache permanente só se aplica quando há relatório real (que é imutável por data). Falha de rede não deve ser confundida com "relatório não existe".

**Key interfaces:**
- `usePreGameAnalysis` deve distinguir três estados: carregando, com resposta (cacheável), sem resposta (retry permitido)
- `retryPreGame()`/`loadPreGame()` devem ignorar o cache quando não há resposta válida gravada
- O card do scanner que expõe o botão de retry deve continuar funcionando sem mudança de contrato visível

**Acceptance criteria:**
- [ ] Abrindo o modal antes do relatório existir, a UI mostra estado de indisponibilidade (não análise vazia "concluída")
- [ ] Clicar em retry com relatório ainda inexistente dispara nova requisição (não devolve o cache)
- [ ] Quando o relatório passa a existir, um retry exibe a análise sem recarregar a página
- [ ] Relatório já existente continua servido de cache sem refetch desnecessário
- [ ] Erro de rede na busca não é gravado como "relatório não existe" — retry segue permitido

**Out of scope:**
- O pipeline que gera o relatório pré-jogo
- Alterar a imutabilidade/política de cache para relatórios que já existem
- Redesign do modal ou do botão de retry na UI
