## Agent Brief

**Category:** enhancement
**Summary:** Servir as respostas do app com headers de segurança CSP, X-Frame-Options e Referrer-Policy, configurados em código versionado

**Current behavior:**
A configuração de rotas/cache do Nuxt só define `Cache-Control` para a home; não há nenhum bloco de segurança, módulo de headers de segurança, nem meta de CSP no `head` da app. Como resultado, as respostas do app chegam sem Content-Security-Policy, sem X-Frame-Options e sem Referrer-Policy — a defesa contra XSS fica só no navegador e o app pode ser iframado (clickjacking). O HSTS já é provido pelo Vercel e NÃO deve ser tratado aqui.

**Desired behavior:**
As respostas servidas pelo app (dev, preview e produção) devem incluir três headers de segurança: `Content-Security-Policy`, `X-Frame-Options` e `Referrer-Policy`. A configuração deve viver no repositório (arquivo de configuração versionado), não em painel/dashboard externo, para que seja revisável em PR e reproduzível em qualquer ambiente. A CSP precisa ser suficientemente permissiva para a app funcionar sem console errors (PWA, fontes, API própria), mas restritiva o bastante para bloquear scripts de origem desconhecida e `javascript:` em navegação.

**Key interfaces:**
- A configuração do Nuxt (bloco de `routeRules`/headers ou módulo de segurança correspondente): deve declarar os três headers de resposta para as rotas do app
- A política CSP: deve cobrir `default-src`, `script-src`, `style-src`, `img-src`, `connect-src` (API própria + origem do snapshot de scanner) e `frame-ancestors`, incluindo `'self'` e as origens que a PWA/serviceworker exige
- `Referrer-Policy`: valor que não vaze a URL completa para terceiros (ex.: `strict-origin-when-cross-origin`)
- `X-Frame-Options`: `DENY` (ou `SAMEORIGIN` se houver iframe interno intencional)

**Acceptance criteria:**
- [ ] `curl -I` numa rota do servidor dev/preview local retorna `Content-Security-Policy`
- [ ] `curl -I` retorna `X-Frame-Options` com valor `DENY`/`SAMEORIGIN`
- [ ] `curl -I` retorna `Referrer-Policy` com valor não-vazador
- [ ] A configuração está num arquivo versionado no repo (diff visível em PR), não num dashboard externo
- [ ] A app carrega sem erros de CSP no console do navegador (login, scanner, gráficos, fontes e PWA funcionando)
- [ ] HSTS não é adicionado neste escopo (já provido pelo Vercel)

**Out of scope:**
- HSTS (já existe no Vercel)
- Configuração de headers fora do repo (dashboard do provedor)
- Reescrever a configuração de cache já existente
- Mitigar o XSS por `href` da issue 01 (a CSP é defesa adicional, não substituto)
