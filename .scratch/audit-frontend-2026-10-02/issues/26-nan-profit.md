## Agent Brief

**Category:** bug
**Summary:** Métrica "Lucro efetivo" renderiza `NaN%`/`Infinity%` quando `medLoss` é null/undefined ou zero com sinal errado.

**Current behavior:**
O cálculo `(ev / -medLoss) * 100` só protege contra `medLoss === 0`. Com `medLoss: null` (modelo sem perdas registradas), `-null` vira `-0` e a divisão produz `NaN` ou `-Infinity`; com `undefined`, produz `NaN`. O guard atual não cobre esses shapes e o `formatNumber` renderiza literalmente `"NaN%"`. Os schemas da API são passthrough e não validam campos numéricos, então o shape chega como está.

**Desired behavior:**
A métrica exibe um valor finito sempre: quando não há base de cálculo válida (`medLoss` ausente, zero ou resultado não-finito), o card mostra o mesmo fallback numérico já usado para divisão inválida (0) ou placeholder neutro — nunca `NaN`, `Infinity` ou `-Infinity`. Com dados válidos, o cálculo é idêntico ao atual.

**Key interfaces:**
- Cálculo do "Lucro efetivo" no card de métricas: guarda de divisão cobre `null`, `undefined`, `0` e resultados não-finitos (`Number.isFinite`)
- `formatNumber()`: defesa adicional opcional — nunca imprimir `NaN`/`Infinity` (mantendo contrato atual para entradas válidas)

**Acceptance criteria:**
- [ ] `medLoss: null` → exibe valor finito (ex.: `0%`), nunca `NaN%`
- [ ] `medLoss: undefined` → idem
- [ ] `medLoss: 0` (ou `-0`) → idem, nunca `-Infinity%`
- [ ] Dados válidos (ex.: `ev: 5, medLoss: -2`) → resultado calculado inalterado
- [ ] Testes unitários cobrem os quatro shapes (null, undefined, zero, válido)
- [ ] `lint`, `test:unit` e `build` passam

**Out of scope:**
- Validar schemas numéricos no backend
- Refatorar os demais cards de métrica
- Alterar a fórmula de negócio do lucro efetivo
