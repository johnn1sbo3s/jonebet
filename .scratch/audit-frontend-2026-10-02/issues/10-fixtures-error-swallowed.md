## Agent Brief

**Category:** bug
**Summary:** Falha ao trocar data/origem na página de fixtures deve exibir erro visível e não deixar a lista antiga sob a data nova.

**Current behavior:** Quando a busca falha, o `catch` escreve uma ref de erro que o template nunca lê, e `fixtures`/`bets` só mudam em sucesso. O usuário vê a lista da data ANTIGA com o date picker já na data nova, sem nenhuma mensagem — e a ref de erro é código morto (escrita, nunca lida).

**Desired behavior:** Em falha, a página exibe uma mensagem de erro perceptível e oferece tentar novamente. A lista da data anterior não permanece apresentada como se fosse da nova data — ou é limpa, ou fica explicitamente marcada como desatualizada junto do erro. Ao recuperar (retry ou nova seleção), os dados novos aparecem e a mensagem some. O código morto de erro é eliminado ou passa a ser de fato consumido pelo template.

**Key interfaces:**
- Estado de erro da página de fixtures: deve ser lido pelo template (mensagem + ação de retry), não apenas escrito
- `fixtures`/`bets`: em falha de busca, não devem continuar servindo o conjunto anterior como se fosse o atual
- A ref de erro hoje existente: usar no template ou remover por completo — não pode ficar escrita e não lida

**Acceptance criteria:**
- [ ] Simulando falha de rede ao trocar data/origem, aparece mensagem de erro visível na página
- [ ] Em falha, a lista da data anterior não é exibida como se fosse da data nova
- [ ] Há como tentar novamente após o erro (retry/repetir a busca) sem recarregar a página
- [ ] Sucesso após o erro limpa a mensagem e exibe os dados da data selecionada
- [ ] Não permanece nenhuma ref de erro escrita e nunca lida no código da página

**Out of scope:**
- Mudar formato, endpoint ou semântica dos dados de fixtures/bets
- Refatorar os estados de loading da página
- Aplicar o mesmo tratamento em outras páginas (issue separada)
