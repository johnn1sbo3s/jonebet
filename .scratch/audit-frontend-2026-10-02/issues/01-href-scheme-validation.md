## Agent Brief

**Category:** bug
**Summary:** URLs externas exibidas em links sem validação de esquema podem executar `javascript:` no clique (XSS via href)

**Current behavior:**
O card de scanner exibe um link externo para o Flashscore cujo `href` vem diretamente do campo de URL do payload do snapshot de scanner, com `target="_blank"`. O payload passa por uma validação de schema permissiva (objeto com campos extras aceitos) que não valida esquema/URL nenhuma. Não existe, em nenhum ponto do app, checagem de esquema (`https`, `sanitizeUrl` etc.) antes de usar URLs externas em `href`. Se o snapshot for comprometido ou o campo manipulado no pipeline de scrape, um valor `javascript:...` executaria JavaScript no contexto da app quando o usuário clica.

**Desired behavior:**
Antes de renderizar qualquer URL externa como clicável, o sistema deve validar o esquema: apenas `http:` e `https:` são aceitos. URLs com esquema diferente (por exemplo `javascript:`, `data:`, `vbscript:`) ou malformadas não devem virar link clicável — o botão/âncora não deve ser renderizado ou deve ficar sem `href` (não clicável), sem quebrar o resto do card. A validação deve acontecer de forma centralizada/reutilizável, de modo que qualquer URL externa futura passe pela mesma checagem. O comportamento atual para URLs `https` válidas não pode mudar.

**Key interfaces:**
- A função utilitária de montagem de URL do Flashscore (que constrói a URL de um jogo a partir do ID): deve expor também uma checagem/validação de esquema reutilizável para URLs vindas de payload externo
- O ponto de renderização do link externo no card de scanner: deve consumir a validação de esquema e suprimir o link quando a URL for rejeitada
- O schema de validação do payload do snapshot: deve garantir que o campo de URL só aceite strings com esquema `http`/`https` (ou ser rejeitado no ponto de uso, desde que de forma centralizada)

**Acceptance criteria:**
- [ ] Uma URL `https://...` válida renderiza como link clicável com `target="_blank"` inalterado
- [ ] Uma URL `javascript:alert(1)` vinda do payload NÃO resulta em link clicável (sem `href` executável), sem erro de runtime no card
- [ ] URLs com outros esquemas não-HTTP (`data:`, `vbscript:`, esquema ausente/malformado) também são suprimidas
- [ ] A checagem de esquema é centralizada em um ponto reutilizável (não duplicada no template)
- [ ] Testes unitários cobrem: `https` aceito, `http` aceito, `javascript:` rejeitado, valor malformado rejeitado

**Out of scope:**
- Alterar o `rel="noopener noreferrer"` ou o comportamento de `target="_blank"` já existente
- Auditoria de outras URLs externas do app além do link de fixture em si (a reutilização futura é desejável, mas a implementação só precisa cobrir este link)
- Validação da integridade do pipeline de scrape/snapshot na origem
- Adicionar CSP (é a issue 02)
