## Agent Brief

**Category:** bug
**Summary:** Poll de 500ms do age-gate do PWA nunca é cancelado se o gate não for dispensado; timer de 2Hz roda a sessão inteira.

**Current behavior:**
O composable de instalação PWA inicia um `setInterval` de 500ms que só se autocancela quando o age-gate é dispensado. Como o composable é singleton e não expõe dispose, se o gate nunca for dispensado (inclusive no app instalado), o timer lê localStorage a 2Hz indefinidamente por toda a sessão.

**Desired behavior:**
O poll existe apenas enquanto necessário e tem caminho de cancelamento: quando o gate é dispensado, o intervalo é limpo (como hoje); quando o composable não tem mais propósito para o poll (gate já dispensado no boot, ou teardown do consumidor), nenhum timer sobrevive. Não deve haver caminho em que um timer de 500ms permaneça ativo para sempre sem dono.

**Key interfaces:**
- `usePwaInstall()`: expõe caminho de cancelamento/verificação no boot — se o gate já está dispensado ao iniciar, o poll nem nasce; se nasce, há dispose/limpeza garantida
- Estado de age-gate (`isAgeGateDismissed()`): única fonte de verdade que o poll observa

**Acceptance criteria:**
- [ ] Com gate nunca dispensado, existe caminho que cancela o intervalo (dispose/limpeza) e após ele nenhum callback dispara mais
- [ ] Com gate já dispensado no boot, nenhum `setInterval` é criado
- [ ] Gate dispensado em runtime ainda interrompe o poll imediatamente (comportamento atual preservado)
- [ ] Sintoma original eliminado: sessão com gate aberto não mantém polling ativo para sempre sem dono
- [ ] Teste cobre: boot com gate dispensado (sem timer) e dispose com gate pendente (timer limpo)
- [ ] `lint`, `test:unit` e `build` passam

**Out of scope:**
- UX/visual do age-gate
- Trocar polling por listener de evento (aceitável, mas não obrigatório)
- Outros composables/timers do app
