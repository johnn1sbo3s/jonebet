## Agent Brief

**Category:** bug
**Summary:** Valor `version` do long-polling do scanner interpolado cru na query string sem URL-encoding

**Current behavior:**
O long-polling do scanner monta a URL de polling concatenando o `lastVersion` (extraído do campo `version` da resposta do snapshot) direto na query string quando não é nulo: `${base}?v=${...}`, sem `encodeURIComponent`. Quem controla a resposta de scanner.jonebet.xyz já controla a origem (impacto autorremesso), mas um valor não-numérico com caracteres especiais pode quebrar o request ou injetar parâmetros na própria chamada de polling.

**Desired behavior:**
O valor de `version` deve ser URL-encoded antes de entrar na query string do polling. A lógica de não anexar o parâmetro quando o valor é nulo/ausente deve ser preservada. O polling deve continuar funcionando normalmente com o payload atual, e valores malformados não devem produzir URL malformada.

**Key interfaces:**
- A montagem da URL de long-polling no scanner: o parâmetro `v` deve passar por `encodeURIComponent` quando presente; quando `lastVersion` for `nulo`/`undefined`, a URL base continua sem query
- A extração de `version` do payload do snapshot (`parsed.version`): não precisa mudar de tipo/origem

**Acceptance criteria:**
- [ ] Quando `lastVersion` é nulo, a URL de polling não tem query string (comportamento atual preservado)
- [ ] Quando `lastVersion` é um valor normal, o parâmetro `v` é enviado e o polling funciona como antes
- [ ] Um valor de `version` com caracteres especiais (`&`, `=`, espaços, `#`) é codificado e não injeta parâmetros extras na query
- [ ] `npm run lint`/`test:unit` passam sem regressão

**Out of scope:**
- Validar o tipo do campo `version` no payload do snapshot (é responsabilidade do originador)
- Alterar o formato/base URL do endpoint de polling
- Mudar a lógica de retry/backoff do long-polling
